### Remote-name-independent operation

Stage 40 had previously hard-coded `upstream` for fetch, worktree creation, and
rebase even though it accepted a `REMOTE` input for push. This meant an
origin-only repository failed when stage 40 needed local Git work.

Shared resolvers were added:

```text
plugins/shepherd-task/scripts/resolve-repository-remote.sh
plugins/shepherd-task/scripts/resolve-repository-remote.ps1
```

They normalize GitHub SSH, HTTPS, and `ssh://` URLs, then select exactly one
configured remote whose URL matches the manifest `OWNER/REPO`. Remote names
such as `origin` and `upstream` are not special.

Stage 15 and the stage-40 orchestrators use the shared resolver. Stage 40 now
uses the resolved remote consistently for fetch, worktree creation, rebase,
and push. Remote names are not stored in `shepherd-campaign.json`, because they
are machine-local checkout configuration.

Tests cover:

- origin-only;
- upstream-only;
- zero matches;
- multiple matches;
- nonexistent explicit remote;
- explicit remote whose URL does not match the repository.
