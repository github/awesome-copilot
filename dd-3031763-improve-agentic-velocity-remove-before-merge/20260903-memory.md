## Cargo Tracker experiment failure

The unattended Cargo Tracker experiment successfully completed all five
treatment tasks and the first four control tasks.

Treatment:

- issues `#5` through `#9`;
- PRs `#15` through `#19`;
- all merged successfully.

Control:

- issues `#10` through `#13`;
- PRs `#20` through `#23`;
- all merged successfully;
- issue `#14` / PR `#24` failed during stage 30.

The implementation in PR `#24` was correct, but mandatory acceptance evidence
was missing from the PR body. Stage 30 submitted a requested-changes review and
CCA completed another work cycle without pushing a new HEAD. Stage 30 then
correctly ended with a semantic failure:

```text
SHEPHERD FAILED: Copilot completed a follow-up work cycle on PR #24 but did not push a new HEAD within 10 minutes.
```

The Copilot CLI process nevertheless returned exit code `0`.

The old outer orchestrator treated that process exit as success because it
did not inspect the stage's terminal semantic marker. Its additional GitHub
checks were also incomplete:

- it did not require the PR to remain `OPEN`;
- it did not require the PR to remain a draft;
- it checked unresolved review threads but ignored aggregate
  `reviewDecision`;
- consequently it ignored `CHANGES_REQUESTED`;
- it skipped stage 30 entirely whenever an open PR already existed.

It printed `Phase 1 VERIFIED` and incorrectly launched stage 40.

Stage 40 behaved correctly. It inspected the failed prerequisite, recognized
the active requested-changes review, restored PR `#24` to draft, refused to
merge it, and reported failure. The outer stage-25 run then failed because PR
`#24` remained open.

The exact root cause was therefore:

```text
copilot --yolo exit code 0 means the CLI session completed; it does not mean
the invoked shepherd skill completed successfully.
```

The wrapper must enforce both:

1. the stage's explicit semantic terminal outcome; and
2. independently queried authoritative GitHub state.

## Root fix implemented

New cross-platform terminal-outcome assertion scripts:

```text
plugins/shepherd-task/scripts/assert-shepherd-session-outcome.ps1
plugins/shepherd-task/scripts/assert-shepherd-session-outcome.sh
```

They:

- read the redacted Markdown session transcript;
- normalize Markdown emphasis and nested blockquotes;
- select the last line beginning with `SHEPHERD COMPLETE:` or
  `SHEPHERD FAILED:`;
- reject a missing terminal marker;
- reject a final `SHEPHERD FAILED:` marker even if the process exited `0`;
- require the completion marker to identify the exact task and PR;
- use digit-boundary-aware matching so PR `#240` cannot satisfy expected PR
  `#24`, and task `#140` cannot satisfy task `#14`;
- require stage 30 completion text to report readiness;
- require stage 40 completion text to report a merge.

The installers now require and install both assertion scripts:

```text
plugins/shepherd-task/scripts/install-task-shepherd.ps1
plugins/shepherd-task/scripts/install-task-shepherd.sh
```

The PowerShell and Bash task orchestrators were changed:

```text
plugins/shepherd-task/scripts/shepherd-task.ps1
plugins/shepherd-task/scripts/shepherd-task.sh
```

Their new behavior is:

1. Query task state before paid work.
2. If the task is already closed, exit successfully only when an authoritative
   same-repository cross-reference identifies a merged PR that:
   - lists the task in `closingIssuesReferences`; and
   - merged into the exact campaign base branch.
3. If the task is open and already has an open PR, log that stage 30 is being
   resumed rather than skipping it.
4. Always invoke stage 30 for an uncompleted task.
5. Require the stage-30 transcript's final semantic marker to report
   completion for the exact task and PR.
6. Independently require the PR to be:
   - `OPEN`;
   - a draft;
   - based on the exact campaign branch;
   - free of `CHANGES_REQUESTED`;
   - free of unresolved review threads;
   - free of failing or unresolved CI state.
7. Query review threads with paginated GraphQL and evaluate the aggregate
   `reviewDecision`.
8. Invoke stage 40 only after all stage-30 gates pass.
9. Require the stage-40 transcript's final semantic marker to report a merge
   for the exact task and PR before accepting GitHub merge state.
10. Skip stale or deleted individual PR cross-reference candidates rather than
    failing the entire search, while still treating top-level GitHub query
    failures as errors.

The original defect is now fail-closed: the preserved PR `#24` stage-30
transcript is rejected before stage 40 can be launched.
