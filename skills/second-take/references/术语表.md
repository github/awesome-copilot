# 大模型术语速查（与 CoT 质检相关部分）

整理自公开资料，供诊断时对齐术语用。诊断报告里不需要堆术语，但判断"这算哪一类问题"时要用得上。

## 一、Rubric：评测侧的判定结构

Rubric 是**针对单道题目**写的一组检查项清单，一条对应一个 Yes/No 判定问题，Yes ＝ 得分。它不是通用评分表，是题目的专属批改清单。

**五个字段**（写 rubric 的最低要求）：

| 字段 | 含义 | 取值 |
|---|---|---|
| Criterion | 判定点描述 | Yes/No 二元判定句，Yes ＝ 得分；否定式约束必须写成「是否未…」 |
| Type | 客观 / 主观 | Objective（可交给 LLM Judge）/ Subjective（需人或人机混合） |
| Necessity | 显性 / 隐性 | Explicit（题目写明）/ Implicit（需推理得出，如多轮继承、角色延伸、常识） |
| Priority | 优先级 | Must have / Nice to have。判据：「只缺这一条，我能不能接受这个回复」 |
| Dimension | 评测维度 | 指令遵循、过程合理性、结果正确性、写作质量、格式、语气、其他 |

**四类硬伤（下限标准）**：语义（指代不清、主观形容词未操作化、两条共线、拗口）、结构（一条塞多个独立约束或不同维度/优先级、整体与局部冗余包含、自相矛盾、否定式没写成 Yes＝得分）、完备性（漏掉显/隐性约束、包含未命中的分支约束）、正确性（事实错误、推理链错）。

**关键区分**：参考答案＝应该回答什么；评分细则＝整体打分；偏好对＝A vs B 谁好；Rubric＝A 本身满足哪些点。

## 二、进化链：从评估工具到奖励信号

- **Rubric + LLM-as-Judge**：Prometheus 系列奠基，用 rubric 约束裁判模型打分。
- **Rubric 作为 RL 奖励**：RaR（Scale AI/Meta）、RLCF（从指令抽 checklist 做奖励）、RRM（过程级，惩罚跳步）。
- **Reward Hacking**：模型会 hack rubric。两类机制——验证器被欺骗（verifier failure）、rubric 本身设计盲区（rubric-design limitations）。典型代价：**在 completeness / presence 维度上的增益，以 factual correctness / conciseness / relevance 的下降换来**。
- **应对**：梯度正则化、因果 rubric（维度间因果独立）、Think-with-Rubrics（把 rubric 内化进推理链，让模型自我监督）。

## 三、对我们这件事的直接启发

1. **CoT 就是模型自己跑的那套隐式 rubric**。审查 CoT，等于审查它临场给自己定的判定标准是不是漏项、有没有自相矛盾、有没有把没依据的东西当已知。
2. **我们给模型的优化与检查指令本身就是一份 rubric**。写进指令的可量化指标（「每节两处加粗」「4-6 行」「至少 3 条」）会被模型当考核项去"表演"——这正是 reward hacking 的轻量版。已发生的实例：为凑列数限制牺牲了样例表的字段完整性；为满足「可检验」编造精确数字与岗位名。
3. **四类硬伤可以直接拿来审我们自己的检查项**：语义 → 表述模糊；结构 → 前后矛盾、强行推理；完备性 → 覆盖不全；正确性 → 无据引用、常识性错误、倒置已知。它与"四条标准"是两套坐标系：**四类硬伤回答「能不能用」，四标准回答「好不好」**。
4. **LLM-as-Judge 的三种偏见**（位置偏见、自我偏见、长度偏见）提醒：诊断时不要因为 CoT 长就判它全面，也不要因为它在前面出现就默认成立。

## 四、其余术语速查

| 术语 | 一句话 |
|---|---|
| Benchmark | 标准化题库，横向跑分，不等于业务表现 |
| Zero / Few-shot | 不给例题（测泛化）/ 给 1-5 个例题（测上下文学习） |
| Position Bias | 交换顺序结果可能反转，标准解法是 Position Swap + 多裁判投票 |
| RLHF | 采样 → 人类排序 → 训练奖励模型 → 强化学习优化（PPO） |
| DPO | 跳过奖励模型，直接用偏好数据优化，流程更短 |
| Red Teaming / Jailbreak | 红队是防御流程（主动找漏洞），越狱是攻击手段（绕过限制） |
| Guardrails | 输入端拦截、输出端替换，与模型解耦部署 |
| CoT / ToT | 线性推理链 / 多分支生成 + 评估 + 剪枝（成本 3-10 倍） |
| Self-Consistency | 跑 N 次取多数投票：正确路径稳定，错误路径随机 |
| Reflection | 出初稿后自我审查再修订，可多轮 |
| Function Calling / Planning / Memory | Agent 的手 / 拆任务 / 状态持久化（短期、长期、工作记忆） |
| Multi-Agent | 按角色分工协作（MetaGPT、AutoGen、CrewAI） |
| SFT | 用问答对教模型听指令；预训练 → SFT → RLHF / DPO |
| LoRA / QLoRA | 冻结主参数只训低秩矩阵，约 1% 参数；QLoRA 叠加量化 |
| 蒸馏 | 教师模型产数据训学生模型，能力上限不超过教师 |
| MoE | 多专家按需激活，总参数大、激活参数小 |
