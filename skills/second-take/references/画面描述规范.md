# 画面描述（caption）写作通则

> 这套规则来自一份视频画面描述的作业规范，已做脱敏与抽象：
> 去掉来源标识、内部术语（设定区/描述区的原名）、全部原始示例与专有名词，
> 只保留跨工具、跨模型都成立的规则。示例一律用占位符。
>
> **它双向适用**：既用于"看一段视频把它描述清楚"，也用于"把想要的画面写成模型能执行的提示词"。

---

## 一、四条最高原则

下笔之前先过这四条，它们决定"什么该写、什么不该写"。

| 原则 | 含义 | 反例 |
|---|---|---|
| **意图优先** | 一切描述都为核心意图服务。写之前问一句"这个信息服务于核心故事或情感吗" | 写无关背景、路人无意义行为 |
| **精炼与准确** | 精炼＝只写关键动作与典型特征；准确＝**只写能客观核实的信息**，靠猜的一律不写 | 凭画面推测人物关系、前因后果 |
| **典型性与辨识度** | 写能把这个对象从同类中区分出来的特征 | 写该类对象的常态（"老年人皮肤有皱纹"） |
| **写因不写果** | 描述动作与原因，不写它必然导致的结果 | 写"水壶冒出热气"（写了因"放在火上加热"就够了，结果是模型能自己推的） |

四条里**"写因不写果"最反直觉**，也最见功力：写结果是把解读权交出去，写原因才是把画面钉死。

---

## 二、结构：设定区 + 描述区

### 设定区（先登记，后引用）

按顺序登记四类对象，**编号连续不跳号**：

| 板块 | 回答什么问题 |
|---|---|
| **定性** | 这是一个什么视频 / 什么画面？意图是什么？ |
| **场景** | 发生在什么环境里？（主体的"舞台"） |
| **主体** | 谁 / 什么在画面里？ |
| **画面元素** | 后期包装添加的东西（字幕、贴纸、水印、特效字） |

### 描述区

- **概述**：一句话说清核心内容，讲明白"这段讲了啥"，含重要声音信息
- **分镜详述**：按时间顺序描述镜头、景别、被摄对象、情节、声音（人声 / 音效 / 音乐）

### 协同工作，不是三遍复述

**具体内容只在相应板块写一次。** 场景里写了"昏暗的欧式阁楼"，概述与分镜详述里就不再重复，
只在需要时用"在阁楼里……"简短带过。设定区登记的对象，后续用编号指代即可，不再描述第二遍。

这一条违反起来极其自然，是冗余的第一大来源。

## 三、各板块的写法细则

### 定性：只写词，不写句子

定性是**准确的词或短语，不允许写成句子**。四条要求：

1. **剥离具体内容，找所属大类。** 不要停在具体物件上，往上归一层：
   「××垫带货视频」→「运动用品带货视频」；「某人生活回忆片段」→「人物专题纪录片」。
   直接用具体物件指代，说明没找到大类。
2. **意图词要准确，禁宽泛、禁裸奔。**
   - 全面禁用"分享"这类过于宽泛的词，换成"生活记录""日常 Vlog"等能准确表达意图的词
   - **严禁裸奔**：只写"随手拍""动画片""3D 视频"而没有任何修饰语＝意图缺失
   - 区分"广告"与"带货视频"：专业制作、有明显推广意图的才算广告，普通商家自推销是带货视频，别滥用"广告"
   - 负面质量词（低质、画面模糊）谨慎使用，只在明显低于普遍标准时才写
3. **特殊风格、特殊视角、突出色调必须写进定性**：如"2D 日漫风格的××视频""无人机视角拍摄的××视频""低画质黑白胶片"。
   已知 IP 要写名称，且**至少两个平台交叉检索确认后再写**——认错 IP 是硬伤。
4. **定性的来源只能是 UP 或目标，不能从 AI 产物反推。** AI 产物是待修改的对象，不是标准；
   拿它反推"这应该是什么类型的视频/画面"，等于把错误固化成定性，后面所有描述都会跟着歪。
   没有目标、UP 也没说清时，先按上下文推断并在标注里写明依据；推断不出才标「待确认」问用户，不从产物里凑。

### 场景：环境要素

- 写占比大、吸引眼球的元素，**以及与主体有密切交互的物体**
- 写法要求：准确凝练 + 空间逻辑（前景 / 背景 / 左右 / 远近交代清楚）
- **划分标准**：
  - 物理空间发生根本改变 → 划分为新场景
  - 同一物理空间内换视角 / 换机位 → **看背景差异度灵活处理**：
    - 背景差别不大 → 仍算一个场景（一开始就能看见的局部，后面单独给它镜头也不新开场景）
    - 背景差异大 → 算多个场景

### 主体：典型性 + 辨识度

**抓核心**：写 **1-3 个**最主要、最有辨识度、**且能在画面中核验**的客观特征。

- **能少就少**：主体只选必要的，非核心意图不加主体，禁止盲目增加
- **人物特征应写尽写**：发色、发型、妆容、五官、身材、从脸到脚的造型着装、气质。
  **漏掉人物特征属于严重错误**；妆容要写出具体区别（不同妆系之间的差异），不要只说浓妆淡妆；
  妆容普通就别硬凑字数
- **声音属于主体设定**：方言、口音（含外语口音）、明显音色、声音气质、小语种，写在主体里；
  没有特点的普通音色不用写
- **持续态归入主体**：从头到尾坐着 / 叼着烟斗 / 抱着盆栽这类不变的状态，算主体设定，写进主体
- **不写**：职业、人物关系（都属推测）
- **避免主观口语**：不写"长相帅气""鼻梁高挺"这类主观评价
- 人种、年龄段用客观分期，不笼统归类
- 群体主体：一群人动作大体协同时，用概括性动作描述整体
- **主体的方位变化写在分镜详述里**，不写在主体设定里

### 片段之间无记忆（最易错）

- 后续片段复用前面的场景 / 主体 / 元素时，**显式把要用的那段抄过来**，只抄当前片段出现的部分
- 上一段的动作延续到这一段，必须写"××动作持续"——不写就会被当成新动作或已结束
- 编号按顺序，不跳编；**设定了就必须引用**，登记了却不用是纯噪声
- **默认值不赘述**（如主体默认正对画面）

## 四、反向用：给生成模型写提示词

把上面这套反过来，就是提示词的写法——**要写的不是"我想要的氛围"，而是"模型能照着画出来的事实"**。

| 原则 | 写提示词时怎么做 |
|---|---|
| 意图优先 | 先一句说清要什么画面，再补要素，别一上来堆形容词 |
| 只写可核实的 | 不写模型猜不到的隐含信息 |
| 写因不写果 | 要"高级感"→ 落成"冷白主光 + 硬阴影 + 低饱和"；要"紧张"→ 落成"手持微晃 + 浅景深 + 快速切镜" |
| 典型性 + 辨识度 | 给主体 1-3 个能在画面里核验的特征，别堆"帅气""华丽"这类不可核验的形容 |
| 协同不复述 | 定义了的主体 / 风格 / 道具，后面用编号或简称指代，不重复描述 |
| 片段无记忆 | 多镜头任务每个镜头**自成一体**，复用要素要重复写，不写"同上""如上" |
| 持续状态 | 跨镜头持续的动作 / 装束 / 光线逐镜头写明 |
| 默认值不赘述 | 平台默认行为不用写，写了既占额度又可能引发偏移 |
| 已知实体直接用名 | 已存在的 IP、风格、材质名可直接写；不认识的新造词不要编 |

### 给了目标或参考视频时的工作流

1. **看意图**：这段要干什么（叙事 / 展示 / 氛围），先定意图再描述
2. **定性质**：一句话定性，找到所属大类，标出风格 / 视角 / 色调 / IP（需交叉核验）
3. **提设定**：按出现顺序登记场景 / 主体 / 画面元素，编号连续
4. **写描述**：概述一句 + 分镜详述按时间顺序，持续状态标明
5. **回查**：设定里的每一条是否在对应镜头被引用？有没有写了推测？有没有把结果当画面？有没有三遍复述？

## 五、落到质检：caption / 提示词怎么判

C 类（生成类）审查时，除通用检查项外再加这八条判定：

| # | 判定 | 不合格的样子 |
|---|---|---|
| 1 | 是否只写了画面可见的事实 | 出现"氛围感""高级""有故事感"等不可见项，且没落成可见要素 |
| 2 | 是否写因而非写果 | 写"他很愤怒"而不是"攥拳、指节发白、下颌绷紧" |
| 3 | 定性是否找到大类、有无裸奔 | 停在具体物件；或只有"随手拍""动画片"没有任何修饰 |
| 4 | 主体特征是否够且可核验 | 只给宽泛形容；或漏掉人物关键特征；或写了职业、人物关系 |
| 5 | 设定与描述是否对得上 | 设定里登记了却没在对应镜头出现 |
| 6 | 有没有三遍复述 | 场景写了，概述和分镜又原样写一遍 |
| 7 | 多片段是否各自完整 | 出现"同上""延续上一段"，或引用前文却没抄过来 |
| 8 | 持续状态是否写明 | 跨镜头持续的动作 / 装束没标"持续"，被当成新动作 |

与通用检查项的对应：1、2、3、4 → 表述模糊；5、8 → 前后矛盾；6 → 冗余（节内重复）；
7 → 覆盖不全。判定归类仍走通用检查项，这八条是该场景下的具体抓手。

## 六、caption 谁来写：默认我们写，留给用户改的入口

用户给了 UP 和目标视频（或参考视频）时，**caption 默认由我们写，不要让用户先写**。
他把视频发过来就是为了省事，把最难的一步推回去等于没干活。

但"我们写"不等于"我们说了算"。画面意图的最终解释权在用户手里，所以写完必须留修改空间。

### 四条做法

1. **单独成块、逐条编号。**
   caption 放在独立的一段，设定区按 `<场景1>` `<主体1>` `<画面元素1>` 编号，
   描述区按片段分条。用户才能说"主体 2 改成……""场景 3 和 4 合并"，而不是对着一整段无从下手。

2. **不确定的判断显式标注「待确认」。**
   这几类最容易判断错，且错了会一路带歪后面的提示词：
   - 定性归到哪个大类（往上归一层时可能归类偏）
   - IP / 品牌 / 已知角色是否认对（认错是硬伤，至少两个来源交叉核对；核不动就标待确认）
   - 主体数量（能少就少，但可能漏了用户认为重要的主体）
   - 场景拆分粒度（同一空间换机位时，合并还是拆开是判断，不是事实）

   写法：`（待确认：判定为××，依据是××；若你认为是××，改这一条即可）`。
   **标注待确认不等于免责**——仍要给出当前最优判断，不能空着让用户填。

3. **给出可改项清单。**
   交付时附一句"这几处最常需要你改"，点名 3-5 个：定性的粒度、场景是否合并或拆分、
   主体是否增减、某元素是否保留、描述的详略程度。用户知道能改什么，才会真的去改。

4. **仅在允许额外说明时，收尾询问里留一个明确指向 caption 的方向。**
   不要只问提示词要不要调整——caption 才是上游。例：
   「若定性或场景划分与你的意图不符，指出第几条，我按你的改并同步更新提示词。」

### 三条纪律

- **用户改过的 caption 以用户为准，第二轮不得悄悄改回去。**
  把用户改过的判断"优化"回我们的版本，是最容易被忽略的一种版本退步。
- **caption 与提示词分开交付，不混在一起。**
  caption 是上游描述，提示词是下游指令。改了 caption，提示词要同步更新——混在一起改不动。
- **caption 里的推测必须标注，不能因为是我们自己写的就当事实。**
  「所见即所得」对我们自己也生效：画面上核不实的，写"待确认"或干脆不写。
