# 自生成 rubric 元指令（混合模式）

## 结论先行

**不要二选一，要分工：**

| 谁来写 | 写什么 | 为什么 |
|---|---|---|
| **目标 AI 自己** | 该任务**领域内**的验收标准 | 每个对话需求不同，我们没有各领域的判定知识，让它先定义"这个领域什么叫好" |
| **我们** | 上一版**实际犯过**的缺陷（种子条目，3-6 条） | 只有我们看过 CoT 和历版产物，它不知道自己上一版把哪一条删了 |

理由：我们的 rubric 是**事后视角**（看了坏产物才写出条目），只能防住已经见过的错；它自写的 rubric 是**事前视角**（拿到 UP 先定义标准），能防住我们没见过的错。两者覆盖的是不同的错误集合。

## 纯让 AI 自写的三个坑

### 坑 1：自我评分膨胀

它给自己写的标准，会不自觉地写成自己一定能通过的形态（LLM-as-Judge 的 self-enhancement bias）。
**护栏**：每条后面必须跟一句「凭什么判」——依据 UP 的哪句话、哪条常识、或产物里的哪个位置。
**自答时没写依据的条目，一律视为「否」。** 这一条比任何措辞都有用，写依据是被迫兑现承诺。

### 坑 2：它会从自己上一版的坏产物反推标准

这是最隐蔽的一条。上下文里摆着它自己上一版的回答，它写标准时会默认"上一版长什么样，什么就是对的"——
于是上版分了几节、上版用了表格，都变成"标准"，而真正的缺陷（那版的结构本身就是错的）被写成了合格项。

**护栏**：判定标准只能来自 **UP 与常识**，不得仅因本对话中此前某版回答采用了某种形态就把它当成标准；用户明确认可的保留项属于 UP。这句话必须写进元指令。

### 坑 3：写出未操作化的条目

它会写"内容是否合理""表述是否完整""逻辑是否通顺"——这类裸形容词判不了，等于没写。

**护栏**：禁裸形容词。凡是想写「合理 / 完整 / 通顺 / 有帮助 / 充分」，必须落成能判的现象：什么出现即算不合格。

### 共同护栏：rubric 不得进正文

元指令里显式写：这份标准只用于自己判定，**不得输出，也不得写成正文的一节**。

## 可复制的元指令模板

```text
【判定标准：先自己写一份，再按它写】
动笔之前，先针对本次任务自己写一份验收标准，写完再动笔。这份标准只用于你自己判定，不得输出，也不得写成正文的一节。
写标准的规范：
1. 8-12 条，每条一个 Yes/No 问句，答「是」= 合格。约束类写成否定式（「是否未出现……」），保证「是」始终是合格方向。
2. 一条只判一件事。含「和」「并」「且」的拆成两条——一条塞两个要求，判定者给不出 Yes/No。
3. 不许写裸形容词。想写「合理」「完整」「通顺」「有帮助」时，必须落成能判的落点：什么现象出现即算不合格。
4. 每条后面跟一句「凭什么判」——依据 UP 的哪句话、哪条常识，或产物里的哪个位置。写不出依据的条目删掉。
5. 按本次任务自身的结构分组（按章节、按模块），不按「语义 / 结构」这类抽象维度分。
6. 覆盖两类：UP 明写的要求；UP 没写但行内默认必须满足的隐性约束。
7. 标准只能来自 UP 与常识，不得仅因本对话中此前某版回答采用了某种形态就把它当成标准；用户明确认可的保留项属于 UP——上一版的写法不是标准。
8. 你写的标准不得与【可用素材】和【必须落实的修改】里已经给定的要求冲突，也不得放宽它们；冲突时以已给定的为准。
自答时每条必须写出依据，不写依据即视为「否」。

【已知缺陷】
下面这几条是上一版实际犯过的，直接并入你的清单，不要改写、不要放宽、不要用你自己写的条目替换它们：
1. …
2. …
```

**【已知缺陷】不必单列的情况**：如果【必须落实的修改】已经逐条点名了上一版的缺陷，就不要再抄一遍——
违反"同一内容只出现一次"。把上面那段换成一句指代词：

```text
【必须落实的修改】里点名的每一处，即上一版实际犯过的缺陷，直接并入你的清单，不要放宽、不要用你自己写的条目替换。
```

## 与定点修复模式兼容

主体成立时默认是**定点修复**，首次审查也适用（上一版除点名处外原样沿用）。这与让它自写标准不冲突，但边界要写清：

- 它写的标准是**判定用的尺子**，不是**改写方案**。不能因为自己写了"应该分五节"就去改结构。
- 元指令第 8 条必须保留。缺了它，它会用自己新写的标准把定点修复**推翻成重写**——第二轮就是这么把合格内容弄丢的。
- 【已知缺陷】是种子不是全部，它补齐的是**剩余部分**。

## 默认启用，四种情况退回纯 A

**混合是默认**。只在下面四种情况退回只给【成稿自检】、不加元指令：

| 情况 | 为什么 |
|---|---|
| 目标模型明显能力弱（小模型、基础版） | 它写不出像样的标准，多占上下文反而拖累正文 |
| UP 极简（一句话提问，无领域约束） | 生成的标准全是套话，等于没查 |
| 缺陷已完全可枚举，且历版产物稳定 | 没有"我们看不到的错"需要它补 |
| 用户明确要最短指令 | 一次到位的优先级高于覆盖面 |

**退回信号**：产物里出现「内容是否合理」这类未操作化的条目，说明它写不出来，下一轮去掉元指令，别硬撑。

## 一个提醒

让 AI 自写 rubric 不便宜：多一次生成、多占上下文。用户要的是**一次到位**，多花这一步的合理性在于——
它换来的是"少粘一轮"。如果目标模型明显写不出像样的标准（产物里出现"内容是否合理"这类条目就是信号），
下一步就退回模式 A，别硬撑。

**用户确认的保留项**：用户明确认可或指定保留的既有内容属于追加 UP，应列入保留清单；其效力来自用户确认，不来自 AI 曾经生成过。用户认可表达不等于证实其中事实，事实仍须核对。
