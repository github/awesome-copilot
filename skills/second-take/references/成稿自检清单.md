# 成稿自检清单（给目标 AI 用 · 嵌进重拍单）

## 它解决什么

现在的流程是单向的：**我们写指令 → 目标 AI 闷头写 → 我们审产物 → 再写一轮指令**。
问题在于，目标 AI 的推理链里没有"什么算好"的标准，它只能凭默认习惯写。我们发现的缺陷（重复、占位符不干净、排比串、
结构里漏项）它自己其实**能查出来**——前提是有人把标准摆到它眼前。

**成稿自检**就是在重拍单末尾加一段 Yes/No 问句，让目标 AI 在输出正文之前逐条自答。
答「否」就改完再输出，自检过程与结论不进正文。这把"事后打回一轮"变成"当场修一次"。

对应评测侧的概念：**Think-with-Rubrics**（把评分标准内化进推理链），优于生成后再用 LLM-as-Judge 打分。
我们的场景里外部 judge 就是用户本人，代价是来回粘贴，所以内化收益更大。

## 写法规范

### 一、格式：Yes/No 二元问句，Yes ＝ 合格

借 rubric 的 Criterion 规范：**一条只问一件事，能明确答是或否**。
约束类条目写成否定式——「是否**未**出现……」，这样"是"仍然是合格方向，避免模型在反向问句上判错。

### 二、只写【输出要求】没写过的东西

硬约束 10：同一段内容在指令里只出现一次。
【输出要求】已经点名的禁用词表、篇幅、占位符规则，**自检里用指代词带过**，不要重列：

- 错：「是否出现了「嗯」「用户问的是」「我需要」……？」
- 对：「【输出要求】里点名的思考腔与元要求措辞，是否一次都没出现？」

自检清单承载的是**内容层面、跨段落层面**的检查——重复、归属、条目齐全、内部自洽、结构漏项。
这些是【输出要求】逐条列举时容易漏掉的东西。

### 三、自检过程不得进正文

两条硬约束同时生效：

1. 自检过程、自答记录、"经检查……"这类话**不得出现在正文里**——那是元要求污染。
2. 自检清单本身**不得变成正文的一节**（不许写成「## 成稿自检」然后逐条写在正文里）。

在指令里显式写一句：**自检在输出之前完成，正文里不出现任何自检痕迹。**

### 四、加兜底句，防 reward hacking

可计数的要求会被模型当考核项"表演"。自检条目本身也是一种指标——模型可能为了让答案全「是」而**删内容**。

必须跟一句：**任何一条答「否」时，改的是内容本身，不是删掉被检查的对象。**
典型反例：为了「同一句判断没出现两次」而把其中一个位置的内容整段删除。正确做法是保留内容、改写其中一处。

### 五、条目数与颗粒度

10-12 条为宜。少于 8 条覆盖不住，多于 15 条模型只在推理链里走形式。
每轮迭代**只保留与本轮修改相关 + 上一版反复犯的**，不要把通用条目全堆上去。

### 六、主观条目要标出来，别写成可机械判定

「通顺」「自然」这类是主观维度（Type: Subjective），写不出 Yes/No 的硬判据。
写法是让它落到可感知的现象上，而不是造一个假指标：

- 错：「通顺度是否达到 8 分以上？」（编指标）
- 对：「通读一遍，是否存在需要回读才能断句的长句、翻译腔句式，或「首先 / 其次 / 最后」的套式？」

## 可直接改写的模板

```text
【成稿自检】
正文写完、输出之前，逐条自答下面这些问题。全部为「是」才输出；任何一条为「否」，改完再输出。
自检在输出之前完成，自检过程、自答记录、以及「经检查……」这类表述一律不得出现在正文中，也不得写成正文的一节。
任何一条答「否」时，改的是内容本身，不是删掉被检查的对象。
1. …
```

条目模板（按本次内容替换占位符）：

| 条目 | 检查什么 | 类型 |
|---|---|---|
| 同一句判断是否在两个位置出现（含一节正文与它自己的样例） | 重复 | Objective |
| ××标准里的判定动作是否只出现在××一节 | 跨节归属 | Objective |
| ××表的×类是否齐全，有没有为了贴合行数删条目 | 条目齐全 | Objective |
| ××表两行示例是否各自内部视角/口径一致，且例子没有与××表重复 | 内部自洽 | Objective |
| ××清单的每条是否都是正文没写过的动作，没有复述正文 | 样例增量价值 | Objective |
| 是否出现三个以上「加粗名词 + 同一句式」的并列串 | 排比公式 | Objective |
| 是否按用户要求结束，未在只要正文等场景追加询问或自行豁免字数限制 | 结构漏项 | Objective |
| 【输出要求】里点名的思考腔与元要求措辞，是否一次都没出现 | 措辞污染 | Objective |
| 篇幅是否在【输出要求】给的区间内，且没有为凑字数注水 | 篇幅 | Objective |
| 是否有为省字数而省略成分的句子（"也知道"写成"也知"、"可以使"写成"可使"、缺"的 / 了 / 是"、把判断句写成"……而非……"） | 成分完整 | Objective |
| "我"字开头的句子是否未超过给定配额，且集中在开头与结尾，中间有没有连续两句以上的主观句 | 人称密度 | Objective |
| 通读一遍，是否存在需要回读才能断句的长句、翻译腔句式，或套式连接词 | 通顺 | Subjective |

## 与自查 rubric 的分工

| | 成稿自检清单 | 重拍单自查 rubric |
|---|---|---|
| 谁用 | 目标 AI（在推理链里） | 我们（交付前） |
| 查什么 | 产物本身 | 我们写的指令 |
| 何时 | 生成时 | 交付前 |
| 形式 | 10-12 条 Yes/No | 五字段完整表 + Must-have 精简版 |

两者都要有。成稿自检管产物质量，自查 rubric 管指令质量——指令本身有洞，自检再严格也补不回来。

## 条目不够时：让目标 AI 自己补一份

本清单的条目来自**我们看到的错**，覆盖不到陌生领域的标准。需要时再加一段自生成 rubric 元指令，让它按规范写一份领域标准，与本清单合并自检。写法、护栏与模式选择表见 `references/自生成rubric元指令.md`。
