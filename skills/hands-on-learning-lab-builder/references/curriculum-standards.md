# Curriculum standards — v0.2

Create a complete blueprint before detailed module generation. For each major concept include purpose, prerequisites, implementation location, alternatives, learner task, validation, controlled failure, recovery, and explanation/assessment.

Use **Understand → Deploy → Run → Modify → Break → Recover → Explain** when meaningful; local-only labs may use setup instead of cloud deployment. Avoid artificial failure exercises for trivial topics.

Order lessons by real implementation dependencies. Budget time for setup, coding, tests, troubleshooting, and review. Challenge infeasible scope rather than silently shrinking depth.

**Implementation-first:** The learner should create or change working artifacts, not just read a completed solution. Supply an incomplete starter, separate reference answer where appropriate, measurable acceptance criteria, reproducible verification, and progressively more specific hints. Give full code on request. Each lesson should identify the state inherited from previous lessons and state required by the next.

Explain concepts in clear language, point to actual files, include example inputs/outputs, and discuss alternatives and trade-offs. Distinguish repository implementation, learning simplification, and production needs. Name safe recovery and cleanup for failures or costly resources. Do not invent execution evidence.
